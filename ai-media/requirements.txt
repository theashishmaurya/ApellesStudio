# What the `ai-media/` sidecar directly needs (D-184/D-189). MLX, Apple Silicon.
#
# **This file no longer describes a separate venv (D-314, 2026-09-12).** It used
# to open with: "deliberately NOT installable alongside ai/requirements.txt —
# `mlx-vlm >= 0.6` requires `transformers >= 5.5`, `ai/` pins `transformers < 5`
# for ViTMatte, and pip reports the union as ResolutionImpossible. That is the
# whole reason this is a second venv and a second process."
#
# The dependency half of that is no longer true, and was re-verified rather than
# assumed. `ai/`'s `transformers < 5` was a defensive pin for ViTMatte that was
# never re-tested after it was set: ViTMatte loads and produces a real,
# spatially-correct matte on transformers 5.x, and the full union of both
# sidecars' requirements now resolves and installs cleanly. So both sidecars run
# from ONE shared environment — `ai-env/.venv`, see `ai-env/README.md`.
#
# **The PROCESS half is unchanged.** `ai-media/` is still its own process on its
# own port, supervised independently, for crash isolation and D-084's independent
# idle-unload. D-314 merged the environments, not the processes.
#
# Since D-314 this file is an *input* to the resolver, not the thing installed:
#
#   ./ai-env/setup.sh              # install the shared venv from the lock
#   ./ai-env/setup.sh --relock     # re-resolve BOTH sidecar files, rewrite the lock
#
# The exact-pin discipline below was always right and now applies to every file
# in the set: this stack's resolution is the fragile thing (a same-day prototype
# had mlx-vlm silently upgrade transformers/tokenizers/numpy/mlx-metal out from
# under mlx-audiocraft in a shared venv). Ranges are how that broke. These are
# the versions actually verified working together.
